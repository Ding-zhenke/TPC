## 3. 本轮交付

### 3.1 `ResultReader`（模块 5.1）✅

`cst_solver.Result` 的**批量化 + 可视化**外壳（**不**重复造读取轮子，阶段 5 已把底层做完）。

统一了三件事：

1. **批量**：一次读回全部 S 参数，不用手写循环；
2. **统一口径**：频率一律 `float`、S 值一律 `complex` 或 dB ——
   **不把 CST 的复数外壳漏给调用方**（阶段 4 T6 踩过：
   CST 的 `xdata/ydata` 都是 complex，强转会 `ComplexWarning` / `TypeError`；
   本轮在报告引擎里又踩了一次，见 §8 第 2 条）；
3. **出图 / 出报告**：转交 `report.py`。

关键 API：`read_s_parameters()` / `read_s_parameters_db()` / `value_at()` /
**`peak_position()`** / **`peak_shift()`** / `export_csv()` / `plot_all()`。

> 🔑 **`peak_shift()` 把阶段 4 的原始判据变成了可执行的东西**：
> 「谐振峰偏差 < 1 GHz」此前只是文档里的一句话，没有任何 API 支撑；
> 现在 `ResultReader(a).peak_shift(ResultReader(b))` 直接给出频差。

**可注入**：`ResultReader(source)` 的 source 可以是 .cst 路径，也可以是任何实现了
`read_all_s_parameters()` 的对象 —— 后者让核心逻辑**完全可离线验收**（测试用假对象，
不必造一个含结果的工程）。

### 3.5 `ParameterScan`（模块 5.3）✅

三件事：**枚举组合 → 交给执行器 → 汇总/出图**。

**执行器是注入的**：``runner(point) -> .cst 路径 | ResultReader | 指标字典``。
于是「枚举、唯一命名、聚合、热力图行列对齐、CSV」这些**扫描本身的逻辑**完全可离线验收，
真跑 CST 只是换一个 runner。

- `combinations()` 是**纯函数**（笛卡尔积 + 把参数写进配置 + 走一遍 `validate_config`）——
  轴取值非法会在**枚举阶段**就报错，而不是等跑完 CST；
- `name_for()` 只由参数值决定 ⇒ 唯一、可复现、不撞名；
- 单个组合失败不终止整批，失败项进 `failed` / `last_errors` / CSV 的 status 列；
- `metric_matrix(metric, ax_x, ax_y)` 直接产出热力图矩阵。

> ⚠️ **一个契约细节**：runner 返回**字典**时 `metric_specs` 不会被执行（没有 reader 可算）。
> 这是合法用法，但会记进 `last_errors['_contract']` —— 否则「设了指标却一直没有值」
> 会查不出来。

### 3.6 `BatchModeler`（模块 5.4）✅ —— **明确不做并行**

计划原本写的是 `build_all(parallel=True)` / `run_all(parallel=4)`。**这条路不走**：

- 阶段 5 §5.7.2 已把 CST 并发模型按证据强度分档：本库**实测过**的只有三条
  （一次 `DesignEnvironment()` 起一个新进程、同一工程不能被两个 DE 打开、
  `cst.results.ProjectFile` 可离线读结果）；**同时开 N 个 DE 的许可上限、
  同时提交 N 个求解任务的行为都未验证**；
- 阶段 4 反复强调过「不要开几十个工程窗口留着」。

所以：

1. **只做串行**。传 `parallel > 1` **直接报错**（消息里说明原因），
   **不做静默降级** —— 静默降级会让人以为真的并行了；
2. 每次执行都配一次 `close()`；
3. `design_environment_baseline()` / `close_extra_design_environments()`：
   **进循环前记基线，结束后只关自己开的那些**，绝不碰用户自己开着的会话
   （有专门的用例断言基线里的进程号一个都不动）。

其它：`from_config()` 支持批量 YAML（`models:` 列表）与单配置 YAML；
`export_csv()` 行数 == 模型数；`plot_comparison()` / `report()` 出自包含 HTML。

### 3.7 `GeneticOptimizer`（模块 5.5）✅ —— 并更正了计划的一个前提

计划说：「`tpc_toolkit/ga_optimizer.py` **已存在**独立 GA 实现，本模块只做**桥接**，
不重写 GA」。**核对源码后这个前提不成立**：

| 计划假设 | `ga_optimizer` 的实际形态 |
|---|---|
| 输入 `variables={name: (min,max)}` —— **连续变量** | 基因型是 **0/1 二维图案**，面向**拓扑优化** |
| 「传一个 GA 对象」 | `GA` 是 **dict**（`Gen_Length` / `Gen_Width` / `Gen_No` / `max_iter` / `cross_prob` / `mut_prob`） |
| `pop_init` 返回种群 | 返回 **4 元组** `(pop, fi, all_pop, all_prob)` |
| 算子对**个体**操作 | `crossover` / `mutation` 对**整个种群数组** `(r, c, n)` 原地操作 |
| 随机性可注入 | 用**全局 `np.random`**，复现要先 `np.random.seed()` |
| `selection` 可直接用 | 它自己标了 warning：「保留 2 优 / 替换 3 差」**只在 `Gen_No == 4` 时自洽** ⇒ **本模块不用它** |

所以本模块提供**两条路**，并在代码与报告里写清各自复用了什么：

| 模式 | 基因型 | 复用了 `ga_optimizer` 的什么 |
|---|---|---|
| `mode='continuous'` | 实数向量 | **只借思想**（选择/交叉/变异/精英）—— 实数基因下「交换比特」没有意义，算子自实现。这不是「重写 GA」，是**换基因型** |
| `mode='binary'` | 0/1 二维图案 | **完整复用** `pop_init` / `crossover` / `mutation`（种群级、原地），并用 `np.random.seed()` 对齐随机数 —— 这才是字面意义上的桥接 |

判据（计划原文「优化后目标函数值优于初始值」）：在固定种子下**必然**成立 ——
支持 `seed`（不给也会随机取一个并**写进结果**）、**精英保留**（每代把历史最优原样带进
下一代）、`evaluations` 计数（可断言「≤ 种群 × 代数」）、每代曲线进审计。

## 4. 规格缺口：本轮补齐了什么

### 4.1 YAML 配置的取值域（06 §14.3）✅

原来是 `model.type` 三个取值加省略号 —— 省略号意味着**没有可执行的校验**。现在：

**`model.type` 完整枚举**（与 `topo_templates/` 类名一一对应）：

| 取值 | 类名 | 状态 |
|---|---|---|
| `straight_waveguide` | `StraightWaveguide` | ✅ 已实现 |
| `unit_antenna` | `UnitAntenna` | ✅ 已实现 |
| `grin_lens_antenna` | `GRINLensAntenna` | 计划中（阶段 6 剩余项） |
| `multiport_antenna` | `MultiPortAntenna` | 计划中（阶段 8） |
| `power_divider` | `PowerDivider` | 计划中（阶段 8） |
| `mzi_switch` | `MZISwitch` | 计划中（阶段 8） |

计划中的取值**语法上合法**（配置可以先写出来、结构可以先校验），
但会在 `template_from_config()` 里明确抛「属于哪个阶段、类名叫什么」，
**不会静默变成别的模型**。

**其余字段**的合法取值、单位、范围、默认值全部落在 `config.FIELD_SPECS` 里，
可用 `config.field_help('straight_waveguide')` 逐行打印：

```
[geometry]
  lattice_constant     float [mm] > 0 — 三角晶格常数 a
  topology             enum ∈ {AB | BA} — 拓扑相
  length               int [格] ≥ 1 — 波导长度（晶格数，不含起点偏移）—— 仅 straight_waveguide
  ...
[solver]
  monitors             str_list — 监视器列表，取值 E | H | Farfield
```

**已补的几条关键约定**（原计划没写）：

- `topology` 只接受 `AB` / `BA`（**大写**，`ab` 会被拒）；
- `monitors` 取值就是 `E` / `H` / `Farfield`（来自
  `cst_solver/simulation/monitors.py` 的 `_FIELD_CONFIG`），且**必须是列表**——
  YAML 里写 `monitors: E` 会被明确拒绝并提示写 `[E]`（这是最容易写错的一处）；
- 长度一律 **mm**、频率一律 **GHz**、长度/宽度类晶格数是**整数**；
- `feed.type` / `output.path` / `solver.fmin+fmax` 三处与模板构造参数名不同，
  由 `FIELD_SPECS.ctor` 统一说明（不会出现「文档写 A、签名是 B」的漂移）；
- **字段还要与模板签名对表**：给直波导写 `bend_angle` 会报错并指出
  「那是 unit_antenna 的字段」；
- 接受的字段集合是**从模板构造签名自动推导**的，不维护第二张清单。

## 8. 本轮遇到的问题与更正（留痕）

| # | 问题 | 处理 |
|---|---|---|
| 1 | **`time.time()` 在 Windows 上粒度约 15 ms** —— 同一刻写的两条审计记录 `epoch` **完全相同**（实测），原实现用 `epoch` 排序等于没排；用 `(ts, tool, status)` 去重还会把「同一秒 + 同名步骤」误判成重复 | 改为**以文件追加顺序为准**（JSONL append-only ⇒ 文件顺序就是时间顺序），去重改用每条记录的 `uid`；老记录退回内容四元组（并去掉 `epoch`） |
| 2 | **报告引擎在复数 S 参数上直接崩** —— `_split_xy` 对第二列做了 `float()`，而 CST 返回的是 complex ⇒ `TypeError`。这是**同一个坑第二次**（阶段 4 T6 是 `ComplexWarning`） | `_split_xy` 不再强转第二列，复数交给 `_to_db()` 取模值；补了专门用例 |
| 3 | **参数存档会覆盖** —— 文件名时间戳只到秒，同一秒两次 `archive_parameters()` 撞名覆盖，而「存档不覆盖」是对外承诺 | 时间戳加微秒 + `_unique_path()` 冲突兜底（`-2`/`-3`…） |
| 4 | **时间线在「所有步骤耗时 < 1 ms」时谎报「没有数据」** —— 原写法用 `if r.get('duration_s')` 过滤，`0.0` 是假值 | 改为判 `is not None`；全为零时照画（条宽用最小值）并在图下注明 |
| 5 | **`validate_config` 对「计划中的模型类型」直接报错** —— 类还不存在 ⇒ 拿不到签名，与「语法上合法、建实例时才说未实现」的设计矛盾 | 计划中的类型改为**放行语法校验**并附 `_warnings`（「字段未与模板签名核对」），真正的「未实现」由 `template_from_config()` 抛，消息里带阶段与类名 |
| 6 | **06 §14.4 的「8 处优化」记录不准**（见 §4.2） | 重新定性为「验证标准不可测量」并改写判据；原文留在 §4.2 备查 |
| 7 | 🔴 **`ga_optimizer` 的实际形态与计划的假设完全不同**（见 §3.7）—— 它是**二值/拓扑** GA（`GA` 是 dict、`pop_init` 返回 4 元组、算子对**整个种群数组**原地操作、用全局 `np.random`），而计划要的是**连续变量**优化；`selection()` 还自带「只在种群为 4 时自洽」的硬编码缺陷 | 分两条路：连续模式只借思想（实数基因下比特算子无意义），二值模式**完整复用**其算子。`selection()` **不用**并有专门用例断言它没被调用；同时 `np.random.seed()` 对齐随机数以保证复现 |
| 8 | **`OptResult.improved` 假设了「求最大」** —— 求最小时「变好」是**变小**，用它原来的判据会把成功判成失败（测试直接抓到） | `OptResult` 增加 `maximize` 字段，`improved` 按方向判定；并补「最小化时历史最优单调不增」的用例 |
| 9 | **runner 返回字典时 `metric_specs` 被静默忽略** —— 没有 reader 可算，但「设了指标却一直没有值」很难查 | 记进 `last_errors['_contract']`，消息里说明「两者取其一」；补了用例 |
