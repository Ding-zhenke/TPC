### 1.2 核心问题（按严重程度排序）

1. **参数传递爆炸**：3438 次 `para()` 调用，平均每个 notebook 41 次。库已有 `paras()` 和 `set_parameters()` 批量方法，但所有 notebook 都用单个 `para()`。
2. **坐标系统分裂**：预览用三角晶格坐标 `(r,c)`，CST 用直角坐标 `(px,py)`，同一条路径写两遍、算两遍（详见 `02_函数优化清单.md` 第七节）。
3. **大规模复制粘贴**：`tp()`、`plot_power_divider()`、光子晶体超元胞生成（25 行）、求解器 VBA 配置（40 行）在每个 notebook 中完全重复。
4. **库能力闲置**：TPC 库 236 个方法中，大量已有方法未被使用（`paras()`、`save()`、`configure_time_solver()`、`create_waveguide_port()` 等），notebook 用更原始的方式替代。
5. **多端口/复杂结构支持差**：多端口天线（3 端口）、功分器、MZI 开关的路径更复杂（6+ 拐点），手动计算 `px/py` 极易出错。
6. **GRIN 透镜建模不统一**：68 个含 GRIN 透镜的 notebook 中，35 个从 DXF 导入，33 个直接用 `hexagon()` 循环生成，两种方式并存且代码差异大。
7. **结果读取缺失**：84 个 notebook 中只有 52 个调用 `run()`，几乎没有 notebook 用 `result` 类读取仿真结果，仿真后分析靠手动在 CST 里操作。
8. **命名混乱**：`feed1`/`feed2`/`wg1`/`wg2`/`g1A`/`g1B` 等名称手写，多端口结构中容易冲突。
9. **水平层次不齐**：部分 notebook 有完整注释和预览，部分只有裸代码；参数命名不统一（`lf1`~`lf6` 含义随结构变化）。

### 1.3 目标

| 目标 | 量化指标 |
|------|---------|
| 新建模型代码量 | 从平均 200+ 行降到 20 行以内（模板 + 配置） |
| 参数传递 | 从平均 41 次 `para()` 降到 1 次 `set_parameters()` |
| 坐标维护 | 从两套坐标（path + px/py）降到一套（TopoPath） |
| 重复代码消除 | `tp()`、`plot_power_divider()`、超元胞生成、求解器配置 100% 消除 |
| 多端口支持 | 3+ 端口模型可通过配置声明，不需要手动算坐标 |
| 结果自动化 | 仿真完成后自动读取 S 参数/远场并出图 |
| 旧 notebook 迁移 | 优先迁移 20 个核心模型，其余标记 legacy |

**智能推断规则**：

| 推断项 | 规则 |
|--------|------|
| model_type | `path.is_straight()` → 'waveguide'；`path.has_bend()` → 'antenna' |
| topology | 波导默认 'AB'，天线默认 'BA'，可被用户参数覆盖 |
| 端口数 | 波导 2 端口（path 两端），天线 1 端口（path 起点），多端口由模板指定 |
| 监视器 | 波导：E 场；天线：E 场 + Farfield |
| 频率范围 | 从晶格常数 a 估算（a=0.2425 → 300GHz 中心，范围 280-380GHz） |

## 九、风险与注意事项

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| CST 面编号 `pick_face` 不稳定 | 端口位置可能错 | 开发 `get_face_id_by_normal()` 按法向量找面；模板中面编号可配置 |
| 多端口/功分器 path 是树状非折线 | TopoPath 单路径不够用 | 阶段三扩展多路径管理，或 TopoModeler 支持 path dict |
| GRIN 透镜两种方式（hexagon/dxf）差异大 | 统一接口困难 | lens.py 内部分支处理，对外统一参数；dxf 方式保留文件路径参数 |
| 旧 notebook 水平层次不齐 | 迁移时参数提取困难 | 优先迁移结构清晰的核心 notebook；复杂的手动分析 |
| CST 自动化本身不稳定 | 建模可能随机失败 | 添加重试机制 + 错误日志 + 每步验证 |

### 9.2 注意事项

1. **不删除旧代码**：所有旧 notebook 保留，只重命名加 `_legacy` 后缀，Result 文件夹不动。
2. **不修改 TPC 库核心**：cst_solver 和 mesh_grid 的源码尽量不动，只在 topo_modeler 层封装；需要新增方法时通过继承或 Mixin 扩展。
3. **渐进式迁移**：每迁移一个 notebook 都要仿真验证结果一致，不批量硬迁。
4. **模板参数要全**：每个模板的参数要覆盖旧 notebook 中出现的所有变体，不能遗漏。
5. **坐标验证是底线**：TopoPath 生成的坐标必须与旧代码逐点一致，这是所有上层功能的基础。
6. **`substract` 拼写保留**：库中方法名是 `substract`，新代码也用这个，不要"纠正"为 `subtract`（除非库加了别名）。
7. **CST 表达式用 `sqr()`**：所有传入 `para()` 的字符串表达式中，平方根写 `sqr(3)`，不是 Python 的 `sqrt(3)`。
