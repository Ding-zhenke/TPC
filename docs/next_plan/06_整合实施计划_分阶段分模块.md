| 项 | 内容 |

| **输入** | 设计稿见 `02_函数优化清单.md` §9.2；**实际落地文件**为 `mesh_grid/tri_grid/topo_path.py`（24,479 字节 / 625 行，含符号坐标扩展） |

| **验证标准** | 见下方 |

**核心功能**：
- `TopoPathBuilder`：链式构建 `.start().move().turn().line_to().close().build()`

**落地操作**：
1. 复制 `topo_path.py` 到 `mesh_grid/tri_grid/`，调整文件头为 TPC 风格
2. 移除 `if __name__ == '__main__':` 自测块（移到测试文件）

4. 编写 `mesh_grid/tri_grid/tests/test_topo_path.py`（落地时为 15 项，现有 **16** 项）

**验证标准**（必须全部通过）：

### 模块 2.4：CrystalBuilder（核心）

| 项 | 内容 |
|----|------|
| **功能** | 构建拓扑光子晶体三角孔阵列（最核心的重复代码，25 行 → 1 个函数） |
| **输入** | `app`, `path: TopoPath`, `topology='AB'`, `lattice='a'`, `height='h'`, `large_hole_ratio=0.65`, `small_hole_ratio=0.35` |
| **输出** | `(crystal_a_name, crystal_b_name)` |
| **依赖** | TopoPath（模块 1.1） |
| **修改 TPC 库** | 否 |
| **验证标准** | 见下方 |

**内部逻辑**：
1. 从 `path.get_array_range()` 获取 `(xup, yup, ydn)`
2. `topology='AB'`：VPC-A 用大孔朝上，VPC-B 用小孔朝上；`'BA'` 互换
3. 超元胞生成（每个拓扑相各一次，共 2 轮）：`triangle ×4`（大孔朝上/朝下 + 小孔朝上/朝下）
   → `add ×2` → `subtract ×1` → `rotation(120°, repetition=2)` → `translate ×3`（X 向、Y+、Y−）
4. 两个拓扑相合计 `triangle ×8 / add ×4 / subtract ×2 / rotation ×2 / translate ×6`；
   与 VPC 区域的裁剪由独立的 `intersect_crystal_with_vpc()` 完成，不在本函数内

.. 注意：大孔/小孔的 AB·BA 分配在实现里与「直觉」相反（本库把 l1 固定为大孔，
   而参考 notebook 的 l1 是 VPC-A 的朝上孔、AB 时为小孔）。分配方向已按
   参考工程 `AB_feed/Model/3D/ModelHistory.json` 的历史树核实，详见
   `topo_modeler/builders/crystal.py` 的模块 docstring。

**验证标准**：
- 超元胞有 6 个三角孔（旋转 120° 复制两次）
- 阵列复制范围与旧代码 `xup/yup/ydn` 一致
- AB 型和 BA 型的大/小孔位置互换正确

### 模块 2.5：SolverBuilder

| 项 | 内容 |
|----|------|
| **功能** | 配置求解器，**调用 TPC 库已有方法**，不手写 VBA |
| **输入** | `app`, `freq_range=(300,380)`, `monitors=('E',)`, `calculation_type='TD-S'`, `steady_state=-30`, `parallel_threads=1024`, `gpus=1` |
| **输出** | 无（直接配置 CST 求解器） |
| **依赖** | `cst_solver` 已有方法：`set_frequency_range`, `configure_time_solver` / `configure_fd_solver` / `configure_eigenmode_solver` / `configure_ie_solver` / `configure_asymptotic_solver`, `create_field_monitor` |
| **实现说明** | `configure_time_solver()` **不接受任何参数**；因此 `calculation_type` 用「分派到对应求解器方法」实现（`TD-S`/`FD-S`/`EIGENMODE`/`IE-S`/`ASYMPTOTIC`），非法值抛 `ValueError`。稳态精度与并行/GPU 参数 `cst_solver` 未封装，由 builder 内部下发 VBA |
| **修改 TPC 库** | 否 |
| **验证标准** | 生成的求解器配置与旧 VBA 字符串效果一致（CST 中检查设置） |

**调用的 TPC 库已有方法**（替代 40 行手写 VBA）：
- `app.set_frequency_range(fmin, fmax)`
- `app.configure_time_solver(...)`
- `app.create_field_monitor(...)`
- `app.set_solver_parameter(...)`（并行配置）

### 模块 2.6：TopoModeler 骨架

| 项 | 内容 |
|----|------|
| **功能** | 智能推断 + 流水线编排核心类，所有模板的基类 |
| **输入** | `template_cst='tmp.cst'` |
| **输出** | `topo_modeler/modeler.py` |
| **依赖** | NameManager（2.1）+ 全部基础 builders（2.2-2.5）+ TopoPath（1.1） |
| **修改 TPC 库** | 否 |
| **验证标准** | 智能推断正确，基础流水线（基板+VPC+晶体+求解器）可执行 |

**核心方法**：
- 配置：`set_path()`, `set_topology()`, `set_parameters()`（批量传参调用 `app.set_parameters`）
- 智能推断：`_infer_model_type()`（path 直→波导，有弯→天线）、`_infer_topology()`（波导默认 AB，天线默认 BA）、`_infer_monitors()`（波导 E 场，天线 +Farfield）、`_infer_ports()`（波导 2 端口，天线 1 端口）

## 十一、风险与注意事项

### 11.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| CST 面编号 `pick_face` 不稳定 | 端口位置可能错 | 模板中面编号可配置；**`get_face_id_by_normal()` 按法向量找面已登记为阶段 4 的前置项**（此前只出现在 04 中，未排入任何阶段）。注意 `cst_solver/modeling/picks.py` 已有 `pick_face_at()` / `pick_face_auto()` 可作为实现基础 |
| 多端口/功分器 path 是树状非折线 | TopoPath 单路径不够用 | 阶段 6 扩展 TopoModeler 多路径管理，不修改 TopoPath |
| GRIN 透镜两种方式差异大 | 统一接口困难 | LensBuilder 内部分支处理，对外统一参数；dxf 方式保留文件路径参数 |
| 旧 notebook 水平层次不齐 | 迁移时参数提取困难 | 优先迁移结构清晰的核心 notebook；复杂的手动分析 |
| CST 自动化本身不稳定 | 建模可能随机失败 | 添加重试机制 + 错误日志 + 每步验证 |

### 11.2 注意事项

1. **不删除旧代码**：所有旧 notebook 保留，只重命名加 `_legacy` 后缀，Result 文件夹不动。
2. **不修改 TPC 库核心**：cst_solver 和 mesh_grid 源码尽量不动，只在 topo_modeler 层封装；阶段 1 只新增文件到 mesh_grid/tri_grid/。
3. **渐进式迁移**：每迁移一个 notebook 都要仿真验证结果一致，不批量硬迁。
4. **模板参数要全**：每个模板的参数要覆盖旧 notebook 中出现的所有变体，不能遗漏。
5. **坐标验证是底线**：TopoPath 生成的坐标必须与旧代码逐点一致，这是所有上层功能的基础。
6. **拼写已统一为 `subtract`（旧名 `substract` 保留为弃用别名）**：库中真实现名为 `subtract()`，
   `substract()` 是等价别名，老脚本仍可用。新代码一律写 `subtract()`。
   同类修正还包括 `new_component`（旧 `new_componet`）、`pattern_export`（旧 `patten_export`）、
   历史标签 `" rotation "`（旧 `" roation "`）。规则见 `skills/developer/WORKFLOW.md` §5：
   **加正确名 + 旧名作别名，不允许静默破坏兼容**。
7. **CST 表达式用 `sqr()`**：所有传入 `para()` 的字符串表达式中，平方根写 `sqr(3)`，不是 Python 的 `sqrt(3)`。
8. **修改 TPC 库时代码风格一致**：文件头、Mixin 模式、双接口命名、Google docstring、f-string VBA、4 空格缩进。
